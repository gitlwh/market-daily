# 市场手记 · 美股每日观察

一个可在本机运行的中文市场日报网页。自动收集美股 ETF 行情、财经新闻和美联储公告，整理热门板块、重要新闻候选和板块量价异动，按美东日期保存日报。

## 启动

需要 **Python 3.9 或更高版本**。应用仅使用 Python 标准库和原生 HTML/CSS/JavaScript，无需 npm 安装、数据库服务或 API Key。

```bash
cd /Users/weihengli/coding/market-daily
bash run.sh
```

浏览器打开 **http://127.0.0.1:8765**。首次启动会采集一次；网页“更新数据”可重新采集。采集通常需要数秒，来源超时会更久。没有联网时也能通过“演示模式”查看界面；演示行情、新闻和走势图均为虚构，演示数据不会写入历史日报。

```bash
# 更改本地端口 / 每日采集时间（美东）
bash run.sh --port 8766 --hour 18 --minute 30

# 仅采集一次，适合外部定时任务
python3 server.py --collect-once

# 只补充最新已存日报的中文翻译，不重新取行情
python3 server.py --translate-saved

# 只看历史和演示，不自动联网
bash run.sh --no-schedule --no-startup-refresh
```

按 `Ctrl+C` 停止服务。服务仅绑定本机地址。

## 当前功能

- **市场概览**：SPY、QQQ、DIA、IWM 四只 ETF 作为主要指数的观察代理，附最近日线走势。
- **市场情绪**：0–100 分综合大盘趋势、板块广度、龙头广度、20 日动量、VIX 和当日已收录新闻；显示六项贡献、覆盖率、置信度和逐日历史曲线。
- **11 个行业板块**：热力图、涨跌排序、热度排名、相对 SPY 表现、20 日量比和关联新闻。
- **多策略选股观察**：合并 11 个板块各 10 家固定龙头与每日美股市值前 100，并按代码去重。三套筛选器分别寻找跌后修复、低估值转强和成长强势公司；每项条件显示 PASS、FAIL 或 UNKNOWN，以及实际数值、阈值、日期和来源。
- **本周财报**：位于板块表现和板块热度下方，按周一至周五五个标签页展示当天公司。沿用全周市值至少 100 亿美元、按市值选取前 15 家的范围；每日列表按市值排序，显示预计日期、盘前/盘后时段及一致 EPS 预期。默认打开当周的美东工作日，周末或历史周默认周一；没有入选公司的日期也保留标签。
- **中文新闻**：采集 CNBC 头条、市场、科技、经济、美国栏目及美联储公告，去重、分类、翻译；保留英文原文、来源及时间。默认显示最近 24 小时，可切换美东当日或最近 72 小时，并展示各窗口数量。
- **异动提醒**：绝对日涨跌 ≥ 2%、相对 SPY 涨跌差绝对值 ≥ 1 个百分点，或成交量 ≥ 前 20 日均量的 1.5 倍。
- **历史与导出**：SQLite 按日归档，可选择已收集的日期，下载 Markdown 或 JSON 日报。
- **自动运行**：服务运行期间，每天美东时间 18:00 采集，周末也整理当天新闻；失败或部分失败每 30 分钟重试。完整成功的当日定时任务不会因重启而重复执行。

本地模式的定时器需要电脑保持开机、联网并运行服务；睡眠后恢复会检查当天到期任务，停机期间不会补造历史。下面的 GitHub Actions 云端模式可免去常开电脑，但必须先把项目推送到 GitHub 并在仓库中启用 Pages。

### 无需常开电脑的云端模式

项目包含 `.github/workflows/market-daily.yml`。启用 GitHub Pages 后，GitHub Actions 每天 `23:30 UTC` 自动运行（冬令时 18:30 ET、夏令时 19:30 ET），执行完整采集并部署静态网页；周末仍更新新闻，行情继续标明最近完整交易日。也可以在 Actions 页面手动运行。定时任务可能因平台排队延迟数分钟。

批处理命令为：

```bash
python3 batch.py --output web-data
```

它会原子更新 `web-data/latest.json`、`web-data/index.json` 和 `web-data/reports/YYYY-MM-DD.{json,md}`。只有存在有效日报时才替换最新数据；失败时保留上一份文件。工作流会把 `web-data` 提交回仓库以保留历史，再发布静态站点。网页会先尝试本地 API；找不到 API 时自动改读相对路径下的静态 JSON，因此同一套前端同时支持本机和 GitHub Pages。

首次使用需要把项目放入 GitHub 仓库，并在仓库 **Settings → Pages → Source** 选择 **GitHub Actions**。工作流需要仓库允许 Actions 写入内容；私有仓库是否支持 Pages 取决于 GitHub 套餐。Yahoo Finance 是非官方接口，云端 IP 可能限流；程序会重试个股失败，并保留缺失项而不是写入假值。

## 数据与计算口径

行情适配器使用 Yahoo Finance 的**非官方 chart 接口**，可能延迟、限流或变更。首次上线建议确认各来源状态；生产部署可在 `providers.py` 中替换为有正式授权和稳定性的行情服务。现在的每条报价都保留实际来源时间和交易日期。

11 个板块由以下 ETF 代理，覆盖的是标普 500 的行业切分，并非所有美股或细分主题：[State Street 官方板块列表](https://www.ssga.com/us/en/individual/capabilities/equities/sector-investing/select-sector-etfs)。

| ETF | 板块 | ETF | 板块 |
| --- | --- | --- | --- |
| XLK | 信息技术 | XLC | 通信服务 |
| XLY | 可选消费 | XLP | 必需消费 |
| XLE | 能源 | XLF | 金融 |
| XLV | 医疗保健 | XLI | 工业 |
| XLB | 原材料 | XLRE | 房地产 |
| XLU | 公用事业 | | |

日涨跌 = 最新日线 `close / 前一日线 close − 1`，不是含分红再投资的总回报。相对表现仅在 ETF 与 SPY 的本日、前日两个交易日期都一致时计算。空值不会填成 0；不同交易日期的旧板块不会参与热度及异动计算。

20 日量比 = 本日成交量 / 此前 20 个有效日线成交量均值。盘中日量尚未完成，当天美东 16:15 前不计算量比；没有 20 个完整前置成交量时显示缺失。这个保守规则没有接入交易所假日或提前收盘日历。所有趋势图展示日线序列。

**板块热度是关注度分数，涨跌两侧都可能得高分。** 满分 100，采用可解释的规则：

```text
min(|日涨跌百分数| × 12, 48)
+ min(|相对 SPY 的百分点差| × 10, 20)
+ min(max(20 日量比 − 1, 0) × 12, 12)
+ min(当日已收录关联新闻数 × 4, 20)
```

缺失分项不计分，`heat_complete=false` 标明口径不完整。周末热度结合最近交易日行情和周末当天新闻，两种日期在页面分别显示。

### 市场情绪分数

情绪范围为 0–100：0–20 极度恐慌、21–40 偏谨慎、41–59 中性、60–79 偏乐观、80–100 极度乐观。六项权重分别为大盘趋势 25%、板块广度 20%、龙头广度 15%、SPY 20 日动量 15%、VIX 15%、新闻关键词 10%。缺失分项不记零分，而是按剩余可用权重重新归一化，同时降低覆盖率和置信度。

大盘趋势比较 SPY 与 20/50 日均线；板块广度统计同一交易日上涨的板块；龙头广度统计站上 50 日均线且 20 日动量为正的固定股票；动量把 SPY 20 日涨跌映射到 0–100；波动率综合 VIX 水平和 20 日变化；新闻只分析系统当天实际收录内容的透明中英文关键词。新闻覆盖有限且容易误判，因此权重最低。情绪分数是历史数据的描述，不是未来涨跌预测。

### 多策略选股观察

股票池有两条入池路径：人工维护的每板块 10 家稳定龙头，以及每日从 Yahoo Finance 股票筛选器中筛选美国主要交易所并按公开市值字段排序得到的前 100。两者按代码去重；Nasdaq 公开股票目录用于把市值榜公司映射到 11 个板块。市值榜暂时不可用时仍会筛选 110 家固定龙头，并明确显示部分可用。固定名单与动态榜单解析逻辑都在 `leader_screen.py` 中，可直接审阅。

每项策略独立计算候选状态。技术指标统一使用 Yahoo Finance 完整交易日复权收盘；板块相对表现使用预先固定的 11 只板块 ETF。当前带财年的 EPS 一致预期来自 Nasdaq，季度营收和稀释 EPS 来自 Yahoo Finance。系统每天另存紧凑的预测快照；在积累到 63 个交易日前，同财年预期变化条件显示 UNKNOWN，策略标记为数据不足，不使用今天的数据倒填历史。

“跌后修复”要求较 252 日高点回撤至少 20%、连续 5 日站上 MA50、MA50 较 20 个交易日前上升，且同财年 EPS 预期未继续下降。“低估值转强”要求未来 P/E 至少比同细分行业中位数低 20%、下一财年 EPS 增长、同财年预期未下修、价格站上 MA200，并在 63 日内跑赢板块。“成长强势”要求最近两季营收和正 EPS 同比增长均至少 10%、同财年预期上调至少 3%、价格和 MA200 趋势向上，并在 126 日内跑赢板块。

候选必须同时满足四项初始规则：最近 20 个交易日的最高复权收盘价出现在最近 10 个交易日；该高点相比 60 个交易日前至少上涨 20%；当前复权收盘价比高点回落 5%–12%；当前价格高于 50 日均线，且 50 日均线高于 200 日均线。采集使用最近一个完整交易日，盘中未完成日线不产生信号。拆股和分红使用数据源提供的复权价格处理。

这些阈值尚未做历史回测，只用于产生可进一步研究的候选。页面同时显示未满足项、数据不足和实际行情日期，不把筛选结果称为买入建议。公开行情可能延迟或限流；单只股票失败不会由旧值或演示值补齐。

新闻来源：[CNBC RSS](https://www.cnbc.com/rss-feeds/)、[美联储官方 RSS](https://www.federalreserve.gov/feeds/feeds.htm)。标题和摘要优先显示中文译文，可展开英文原文。新闻“高关注”由宏观政策、财报、公司事件及相关板块等关键词规则筛选，不代表已确认会影响价格。标题和摘要只来自 RSS，覆盖范围有限；系统不推断“某新闻导致某板块涨跌”，也没有接入大模型自动评论。

**为什么凌晨只有几条新闻？** “当日”以美东零点开始，凌晨的新报道通常很少。页面现在默认展示采集时刻前 24 小时的报道，且每条都显示完整日期；不会把昨日新闻算成今日。`news` 仍仅含日报当日新闻，供热度及每日摘要使用；`recent_news` 保留最近 72 小时新闻用于浏览。所有窗口相对已保存的 `generated_at` 计算，旧快照未留存跨日内容时会明确提示。订阅源的篇数和覆盖范围仍有限。

自动翻译使用 [MyMemory 官方 GET 接口](https://mymemory.translated.net/doc/spec.php)，只发送公开 RSS 标题与简短摘要，原文不会被覆盖。中文按原文字段内容散列缓存到 SQLite；重复采集复用译文，内容变化才重新翻译。翻译失败时保留新闻，并在页面说明未译字段。每批优先处理今日标题和摘要，然后处理跨日标题及摘要。

MyMemory 的[匿名免费额度为每日 5,000 字符](https://mymemory.translated.net/doc/usagelimits.php)，程序保守使用其中 4,900 字符；超限后停止新请求并保留原文，因此无法保证每天所有新增新闻都完整翻译。若愿意向该服务提供有效联系邮箱，可自行设置 `MYMEMORY_EMAIL`，其公布的额度为每日 50,000 字符（程序预算 49,000）。程序不会自动读取或发送你的个人邮箱。缓存和预算都跨重启保存；服务端额度仍以服务的实际计算为准。也可用 `--no-translate` 完全跳过在线翻译。

本次已有报道的标题和摘要另做了 AI 中文校对，缓存来源标记为 `AI 中文校对`；后续新增报道默认仍由 MyMemory 自动翻译。机器译文用于阅读辅助，术语和事实以来源原文为准。

所有来源失败时保留上次成功报告，网页显示新一轮采集错误及旧报告时间；部分来源成功时保存当次结果，并保留缺失项和错误详情。不会把旧新闻标成今日新闻，也不会用演示数据补缺。

## 本周财报与分析师数据

财报榜单使用 [Nasdaq 财报日历](https://www.nasdaq.com/market-activity/earnings)，公开接口可能变化或暂不可用。“本周”始终按采集时的纽约周一至周日计算，周末不会偷偷切换成下一周。查看历史日报时，页面展示当时保存的周区间，不会将历史日历标成最新。

“大公司”目前定义为日历返回的美元市值 ≥ 100 亿美元；按市值降序最多展示 15 家，并保留实际成功采集的日期、来源与错误。不同日期可能只取得部分日历，页面会标注覆盖不完整。未取得市值的公司不参与此排名；该名单不是全市场完整清单。日历日期是数据源预期，最终以公司投资者关系公告为准；时间缺失时显示“时段待定”。

**每股盈利预期（EPS）不代表股价涨跌预测。** 当前真实采集提供 EPS 一致预期和覆盖人数，尚未接入可核对的分析师目标价来源，因此目标价栏显示“暂无预测”。页面已预留目标价、参考股价、期限和来源的展示；演示模式中的目标价仅为虚构示例。将来接入后，目标价空间按 `(平均目标价 / 同币种参考股价 − 1) × 100%` 计算，并展示报价时点。目标价空间通常属于较长周期的估值意见，不能当作财报当天的涨跌预测；不会根据盈利预期编造方向。

网页“收集最新数据”和 `python3 server.py --collect-once` 都会同步收集当周财报，继续保存在同一份日报。财报源失败会保留已经取得的行情与新闻，不会改用演示数据。

## 代码结构

```text
market-daily/
├── server.py             # HTTP API、SQLite 归档、后台采集线程、每日调度
├── providers.py          # 行情/RSS 适配、去重、分类、热度/异动、演示数据
├── translations.py       # 中文翻译、内容缓存、每日预算及失败回退
├── earnings.py           # 美东本周财报、大公司排序、EPS 一致预期
├── leader_screen.py      # 板块龙头 + 市值前 100、复权日线与回调规则筛选
├── sentiment.py          # 六项市场情绪分数、覆盖率与置信度
├── batch.py              # 一次性云端采集、原子生成静态 JSON/Markdown
├── .github/workflows/    # 交易日收盘后的定时任务和 GitHub Pages 部署
├── static/
│   ├── index.html        # 页面结构
│   ├── styles.css        # 响应式视觉样式
│   └── app.js            # 数据获取、筛选、图表、历史、详情、导出
├── tests/                # 数据解析、日期口径、调度和 API 测试
├── data/market.db        # 首次启动生成，SQLite 本地归档
├── CONTRACT.md           # 数据结构与 API 约定
└── run.sh                # 启动入口
```

后端三层职责分开：`providers.py` 产出统一的日报对象，`server.py` 负责运行与保存，`static/app.js` 负责展示。未来增加数据源不需要重写页面；增加 LLM 时应读取已采集、有来源的结构化数据，并单独保存生成结果及引用。

## API 与检查

| 接口 | 用途 |
| --- | --- |
| `GET /api/dashboard` | 最新已保存报告、日期列表和运行状态 |
| `GET /api/dashboard?date=2026-09-18` | 指定归档日期，不会自动回退到其他日期 |
| `POST /api/refresh` | 异步采集，重复请求共用正在执行的任务 |
| `GET /api/demo` | 明确标注的虚构示例，不写数据库 |
| `GET /api/export?date=2026-09-18&format=md` | Markdown 下载，格式也支持 `json` |
| `GET /api/health` | 本地服务与采集任务状态 |

```bash
python3 -m unittest discover -s tests -v
node --check static/app.js
```

测试使用固定数据和临时数据库，不依赖在线行情，不污染真实归档。Python 时区数据依赖系统 IANA 数据库；本项目已按 macOS 环境开发。Python.org 的 macOS 安装若缺少默认证书，会使用 `/etc/ssl/cert.pem` 系统 CA，始终校验证书；也可以通过 `SSL_CERT_FILE` 指定可信 CA 文件。不要通过关闭 TLS 验证来修复网络问题。

可选浏览器检查脚本为 `tests/browser_smoke.mjs`，使用 Node 22+ 内置 WebSocket 连接独立 Chrome 调试实例，无需安装前端测试包。先启动本服务，再另开终端运行：

```bash
'/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' \
  --headless --disable-gpu --no-first-run --no-default-browser-check \
  --remote-debugging-port=9223 --user-data-dir=/private/tmp/market-daily-browser-check about:blank
```

在项目目录运行 `node tests/browser_smoke.mjs`，验证筛选、板块详情、演示隔离、导出、断网状态及手机布局，并将截图写入 `test-results/`。需要至少一份成功保存的真实日报以检查导出；测试不会请求新增采集，也不会修改归档。

扩展建议：先接入稳定行情授权与交易所日历，再细分半导体/软件/银行等主题，最后按需要加入带引用的中文摘要和通知。
